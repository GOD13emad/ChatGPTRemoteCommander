## Primary sources and causal interpretation

- [Microsoft GetFolderPath contract](https://learn.microsoft.com/en-us/dotnet/api/system.environment.getfolderpath?view=netframework-4.8.1): empty output is possible. Never combine an unchecked empty root with a protected relative suffix.
- [Microsoft .NET Framework reference implementation](https://github.com/microsoft/referencesource/blob/main/mscorlib/system/environment.cs): InternalGetFolderPath calls SHGetFolderPath and returns empty for most negative HRESULTs. This explains why the script later exposed DirectoryNotFoundException rather than a useful folder-resolution error.
- [SHGetFolderPath](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shgetfolderpathw): the legacy API wraps the known-folder system and can produce an empty result on error. The helper did not request folder creation.
- [KNOWNFOLDERID](https://learn.microsoft.com/en-us/windows/win32/shell/knownfolderid): ProgramData is a fixed folder whose documented defaults include the system-drive expansion. This motivated the isolated SystemDrive control instead of guessing new environment variables repeatedly.
- [ProcessStartInfo.Environment](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.processstartinfo.environment?view=net-10.0) and [Windows environment blocks](https://learn.microsoft.com/en-us/windows/win32/procthread/environment-variables): the explicitly constructed child block replaces inherited context. Parent success does not prove child path resolution.
- [ExpandEnvironmentStrings](https://learn.microsoft.com/en-us/windows/win32/api/processenv/nf-processenv-expandenvironmentstringsw): unresolved variables remain unexpanded. The controlled observation, not a claimed undocumented registry internal, establishes this machine's missing-variable cause.
- [.NET 10 Windows Environment source](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Private.CoreLib/src/System/Environment.Win32.cs): CommonApplicationData uses SHGetKnownFolderPath, then a ProgramData environment fallback if that fails. Thus .NET10 consumers launched without both required OS context and fallback share the exposure; their actual production call has not been run here.

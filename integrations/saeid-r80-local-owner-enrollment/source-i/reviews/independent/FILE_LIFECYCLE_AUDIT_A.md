# R80 production file-lifecycle audit — shared fixture/reader cause

This is one bounded cross-check of bootstrap, Store, ExchangeJournal, native consent, reader and rollback contracts. R78/R79 source remains sealed. No authority files, tasks, keys or installed version were changed by reviewer. Final pins/acceptance belong to the later frozen review.

Shared cause: ordinary fixtures used their own file reader/creation path and therefore did not exercise production requirements for nonempty files and protected, noninherited DACLs. A fixture crypto/restart PASS cannot qualify that OS storage boundary. Two direct mismatches were identified: an intentionally empty initial journal went through the nonempty protected-file reader; native receipt creation inherited its directory DACL while the consumer requires a protected file DACL. These are source invariants, not invented runtime incidents.

## Regression and authority boundary

R80 reader-boundary fixtures call the same held-file/size/tail/initial-marker/head logic as production, bypassing only fixed protected root/ACL admission; actual ordinary invocation of the production root path denies. This is a useful causal regression and must stay labeled `productionAclPositive:false`. It does not prove administrator-owned storage acceptance before UAC. Default production builds must exclude the boundary fixture entry.

The native host must be rebuilt against the R80 derived reader and its exact pinned source. Likewise the receipt-producing helper must be rebuilt against its corrected writer. Neither the frozen R79 executable nor Native J may inherit the new source PASS by filename or version alone. All compiled artifact pins, bundle fields and native helper policy pin must agree.

Future actual acceptance after concrete source review/owner UAC should validate the exact produced files through the production readers, one real owner consent/receipt path and reversible task-only rollback readiness. It must not stop or replay any existing project operation. Only the affected enrollment/storage gate is held; bootstrap/client source work continues independently, with no duplicate943-test suite.

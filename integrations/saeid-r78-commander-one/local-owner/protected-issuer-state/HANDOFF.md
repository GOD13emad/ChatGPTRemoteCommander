## Concrete source implemented

The producer accepts an untrusted authorization request with an exact schema, registered client/callback/resource and protected grant-policy binding. It generates random request ID and nonce, binds S256 challenge, owner/epoch, scopes/actions, profile/root policy and state; the serialized `bound` bytes match the existing native consent helper and JS JSON.stringify digest contract. Duplicate client/state with unchanged input returns the same committed pending record without minting another identity; changed binding, consumed/revoked/uncertain prior state denies.

Production `OpenProtected()` accepts no caller root, identity, public key, policy, verifier callback or authorization boolean. It fixes the ProgramData authority path, checks protected ACL/owner/reparse/parent-delete routes, obtains the actual kernel process token, and requires either actual elevated SYSTEM or the exact elevated enrolled owner. It loads the pinned public consent key and rechecks current enrollment policy for every operation. This is compiled source, **not observed positive protected-host acceptance**. It must eventually be included in an admitted protected native broker/issuer; never elevate this writable managed DLL or invent a public wrapper around its private constructor.

`ISSUER_STORE_FIXTURE_TEST` enables a test-only factory, ordinary fixture files and deliberate child exit injection. Production is separately compiled without that symbol. A metadata test confirms `OpenFixture` and `CrashAt` do not exist in the production assembly. There is no runtime “fixture/approved/elevated” switch in the production request protocol. Fixture ephemeral keys are held only in memory; fixture public-key/policy files never enroll an actual owner.

Operations hold one exclusive file lock. Newly created production state files use an explicit Administrators/SYSTEM-only protected DACL and owner; no pre-existing ACL is repaired. An append-only bounded journal, initialized marker, enrollment digest and separate sequence/hash head establish prepare/commit/consume transitions. Writes use WriteThrough and Flush(true); head publication uses a newly created protected file and replacement under the writer lock. Missing journal/anchor/head, a partial tail, invalid chain/transition, enrollment drift or a head mismatch fail closed and are never truncated/repaired/replayed automatically.

The pending file is published only as part of a prepared/committed sequence. A crash after preparation or publication leaves explicit reconciliation required; it does not regenerate a request or resume a native prompt. Receipt consumption verifies an actual P-256 DER signature and exact request/issuer/owner/epoch/digest/grant/time binding, reserves the receipt identity before terminal consumption and never consumes again after restart. A native owner-denied/timeout receipt becomes terminal denial. Revocation is terminal for that request/grant and affects new authorization only: this library never stops or repeats a project job. Outcomes explicitly return `TokenIssued=false`; no arbitrary signing API exists.

Admission reserves bounded frame/byte capacity for later consume/revoke transitions before pending creation. The current prototype allows at most128 lifetime request identities and4MiB journal data. It stops on capacity; it does not forget old receipt identities or silently start a new epoch. Protected rollover/compaction is a future production gate, not implemented.

# Local owner resource grant — R78 source slice

Source-only cryptographic resource verification, not an installed login or an authorization to execute native actions. `QUALIFICATION.json` qualifies the exact source after a revocation regression: 20 unique cases pass using fresh in-memory P-256 keys and reserved `.invalid` domains. No owner key, access token for a real account, listener, account setting, service or installed Commander was created or changed.

`createLocalResourceGrantVerifier` verifies an ES256 access token and a separately signed, fresh grant-state envelope. The public key must come from independently protected owner enrollment. Token/statement identity, issuer, resource, owner epoch, client, grant, profile, root policy, scopes and action must agree. A token lasts at most 300 seconds; a signed grant-state statement lasts at most 15 seconds. A new dispatch must perform fresh verification. A valid revocation is remembered before denial and is terminal for that grant in the current verifier process. An older active state, conflicting same-sequence state or later active state cannot undo it. Re-enrollment uses a distinct grant identity.

The code does not implement a protected state producer, enrollment, issuance, refresh tokens, native OS authorization or a cold monotonic anchor. Protected-state freshness bounds stale revocation within the declared 15-second window; this is not instant push revocation. Per-process sequence memory does not survive restart, so cold complete-state rollback remains unproven. The result explicitly says `conversationIdentityAuthenticated:false` and `nativeActionAuthorized:false`. Chat correlation and application Full Power are not owner authentication.

Failure history is retained. The initial 15 source tests passed; independent review then proved that throwing on revocation before retaining its sequence allowed a still-current older active envelope to be replayed. The source now validates authenticity, identity, timing and sequence before recording terminal revocation. Invalid, forged, wrong-owner or stale state cannot poison the cache. The B repair runner failed at a wrongly derived Node path before mutation; `QA_B_FAILURE.json` reconciles unchanged source. The fresh C runner preflighted the exact existing runtime and passed all 20 cases. Consumed A/B/C runners are DO NOT RUN.

Next: protected issuer/state producer and enrolled public key, resource HTTP integration behind a separate admitted connection, real owner consent, and real end-to-end negative/positive login tests. Existing legacy source and running jobs must remain unchanged until independent migration and rollback gates pass.
